# Contributing

Thank you for helping make robot runtime assurance easier to inspect and reproduce.

1. Open or claim an issue before a substantial change.
2. Keep algorithms deterministic unless randomness is seeded and recorded.
3. Add a scenario or focused unit test for every behavior change.
4. State modeling assumptions and failure modes in the pull request.
5. Run `pytest -q` and the example CLI before submitting.

Pull requests should be small enough to review as a safety argument, not only as code.
